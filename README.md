# 法律尽调账簿浏览器（MVP）

把企业提供的明细账、序时账、科目余额表、资产负债表和利润表导入本地项目，逐层查看：**科目余额 → 明细分录 → 同号凭证的已导入分录**。原始表格不会被修改。默认仅在本机处理；主动使用 Jev 建议列时，会先确认发送有限的表格预览。

## 运行

需要 Python 3.11 或更新版本。macOS 和 Windows 均可运行源码版。

```bash
python -m venv .venv
# macOS: source .venv/bin/activate
# Windows: .venv\Scripts\activate
python -m pip install -e .
python run.py
```

运行依赖 `openpyxl`（`.xlsx/.xlsm`）、`xlrd`（旧版 `.xls`）、`typesafe-sdk`（Jev）和 `keyring`（系统钥匙串）。桌面界面采用 Python 自带的 Tk；数据使用本地 SQLite。当前提供源码运行方式，尚未制作经过验证的 `.app`、`.dmg` 或 Windows 安装包。

## 试用步骤

1. 启动后点“新建项目”，选择本地 `.sqlite` 文件的保存位置。每个项目/企业建议单独建一个项目文件。
2. 点“导入多份资料”，可一次选多份文件。软件列出自动识别的序时账、科目余额表、资产负债表和利润表工作表，确认后一次导入；不能可靠分类的工作表会列出并跳过。也可点“导入一份资料”逐张检查列映射。
3. 试用 `examples/模拟企业账簿.xlsx` 时，可一次导入其中的“序时账”和“科目余额表”两页。
4. 在“科目总览”选择要看的余额表来源并双击科目，再在“明细记录”双击一行查看凭证分录；可按“会计期间”筛选。查看“往来线索”“核对提醒”“导入记录”。
   科目余额、明细账和凭证窗口各有醒目的“显示／隐藏列”按钮；勾选即可显示或隐藏，也可“全部显示”或“恢复默认”。列设置保存在当前账套，隐藏列不会删除导入数据。字体大小可在“设置”调整，适用于所有账套窗口。
5. 可按关键词搜索科目、摘要、凭证号、往来单位、辅助项；“导出当前明细 CSV”会使用当前科目、关键词和期间筛选。
6. 如需跨表核对，到“核对提醒”点“设置核对范围”，指定会计年度/期间、参与的明细来源、余额表和报表来源，并为需要核对的报表项目勾选对应科目及借贷取值方向。保存后在该页查看金额、差额、口径和来源；差异只提示，不妨碍继续查看明细。
7. 在“明细记录”选中一行点“关注／注释所选凭证”，或在凭证窗口点“关注／注释”。“关注清单”页可查找、修改注释或取消关注；首次选择 MD 路径后，点“一键更新 MD”会重建同一文件。MD 按科目提供索引，每张凭证正文只出现一次；软件外对该文件的手工修改会被覆盖。
8. 点“关联方名单”可在当前账套手动新增名称、别名和备注。明细账的“用户标注关联方”列依据往来单位或辅助核算名称精确匹配；名称命中只是筛查线索，不代表法律上的关联关系已获证实。

### Jev 建议列（可选）

在“设置”输入 Jev API Key，密钥会保存在操作系统钥匙串，不写入账套或偏好文件。导入一份资料时，点“Jev 建议列”，软件会先说明发送范围并请你确认。确认后只发送当前工作表的前 20 行、每行最多 20 列、每格最多 60 字；这些内容可能包含企业名称和金额。不发送整份文件或本地路径。Jev 会建议表类型、表头行和列对应关系，但**不会自行导入**；请核对预览中的期间、借贷方向与金额列，再点“确认并导入”。不用 Jev 时，自动识别和手工映射照常可用。

### 已使用旧版导入过同一工作表

关闭软件后重新运行，打开原来的 `.sqlite` 账套，再导入同一个 Excel 工作表。映射窗口现在有“会计年度”“期间”等字段。确认后若提示来源已存在，选择“是”即可**替换该工作表的旧导入记录**；原始 Excel 不会修改，替换失败会保留旧记录。旧账套会自动增加新字段，但旧分录中缺失的凭证号、期间等信息需要重新导入才能补齐。

对于“日期、会计年度、期间、凭证字、凭证号、摘要、科目编码、科目全名、核算维度、币别、原币金额、借方金额、贷方金额、制单”这种序时账，全部 14 列均可单独映射；没有“往来单位”列时应保持“不导入”。同一凭证后续分录的日期和凭证号留空时，导入器会在连续数据行内继承上一行凭证标识，并保留每行原始内容供核对。

多份余额表是不同时间点的快照，“科目余额”页一次只显示所选的一份，不会把几个月的期末余额相加。“明细账”中的期间筛选也作用于辅助核算和导出；余额表与明细是否覆盖同一期间仍需人工确认。

跨表核对只使用所选来源及期间。余额表本期借贷与明细逐科目比较；资产负债表项目与所选科目的期末余额比较；利润表项目与所选科目的期间发生额比较。报表项目可能汇总多个科目，必须由使用者确认对应关系；空白金额、缺失科目或失效来源标为“待核”，不当作零值或账务错误。重新导入后，如果关注凭证内容发生变化或原凭证无法匹配，标注会保留供复核，暂不写入 MD。

支持 `.xlsx`、`.xlsm`、`.xls` 和 UTF-8 CSV。余额表既支持借贷分列，也支持“余额金额＋余额方向”格式；两行表头可分别识别期初、本期发生、本年累计和期末的借贷列。核算维度明细行不计入科目合计，避免重复相加。资产负债表可识别双侧表头，利润表最多保留三列金额。无法可靠识别的版式仍需逐张校对。公式单元格需要原文件保存了计算结果；如果预览为空，请先在 Excel 中重新计算并保存副本。

## 当前能力与边界

| 模块 | 已实现 | 需要留意 |
|---|---|---|
| 导入 | `.xls/.xlsx/.xlsm/CSV`、多文件工作表自动分类、双层余额表表头、预览与手工映射、可选 Jev 列建议、原行号及 SHA-256 留痕；重复来源可事务性替换 | 现金流量表暂不支持；不能可靠分类的表不会自动导入；Jev 建议须人工确认；多文件期间重叠不自动去重 |
| 浏览 | 科目、明细、凭证分录穿透；虚线表格与温和的借贷区别；三处表格可分别设置显示列；搜索及期间筛选；辅助核算汇总；CSV 导出；余额表来源选择 | “凭证”按会计年度＋期间＋凭证字＋凭证号重组，缺少期间时按日期；并非原始凭证图片 |
| 核对 | 余额滚动、所选余额表与明细本期发生额、确认映射后的报表项目比较、凭证借贷、跨文件疑似重复 | 需人工确认期间、来源和报表项目对应科目；范围不全时标为“待核” |
| 关注凭证 | 账套内标注与多行注释、按科目索引的一键 MD 更新 | 凭证是根据已导入明细重组的，内容变化后需复核再导出 |
| 关联方 | 当前账套手动维护名称、别名和备注，明细与 CSV 标示精确匹配结果 | 不从摘要或模糊包含关系推定关联方身份 |
| 数据 | 本地 SQLite，金额按分存储，原文件不改动 | 未提供文件加密和用户权限；请按案件保密要求保管账套与源文件 |

如果企业仅提供某一科目的明细，点开凭证时可能缺少其他科目分录；“核对提醒”会提示这种可能。没有凭证号的行无法可靠归并为一张凭证。科目名称和编码不一致、父级与明细级科目同时出现在余额表时，使用者需要确认科目级次和统计范围。

## 技术选型与模块

- `ledger_viewer/importer.py`：解析文件、字段映射、金额与日期标准化。
- `ledger_viewer/store.py`：本地数据模型和只读查询；导入操作作为单个事务，失败则回滚。
- `ledger_viewer/checks.py`：独立核对规则，只输出差异，不修改数据。
- `ledger_viewer/reconciliation.py`：按用户确认的来源、期间和项目映射比较报表与账簿。
- `ledger_viewer/voucher_notes.py`：保存关注凭证及注释，生成按科目索引的 MD。
- `ledger_viewer/related_parties.py`：按用户维护名单对往来单位和辅助核算作精确匹配。
- `ledger_viewer/jev_mapping.py`：在用户确认发送预览后，让 Jev 从有限候选列中提出建议；密钥由系统钥匙串保管。
- `ledger_viewer/grid_lines.py`：为可滚动表格绘制浅色虚线分隔。
- `ledger_viewer/ui.py`：桌面窗口；不承担会计计算。
- `ledger_viewer/analysis_api.py`：后续 AI 分析使用的只读候选数据接口，返回源文件哈希和行号。关键词命中仅是线索。

下一阶段继续适配其他真实企业样表（可脱敏）：更复杂的多行表头、合并单元格、金蝶/用友不同列名、辅助核算单独表、借贷方向其他表示法和分月文件覆盖范围。之后再增加“借款与实缴出资”等专题分析；每条提示需链接原始账簿行，并区分账面事实、规则推断和待补证据。
