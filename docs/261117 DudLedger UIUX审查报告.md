## 一、结论先行

DudLedger 已经具备完整的本地尽调查账闭环：导入预检、分录重组凭证、跨页选择、关注与备注、问题归集、快照留存、AI 发送前确认均已落地。最新版还已经具备筛选条件 chips、表头筛选与排序状态、问题目录搜索、凭证紧凑高度、固定合计、折叠备注和 AI 高级选项收纳。

因此，本报告不再把这些已有能力写成待办。当前最需要解决的仍然不是“界面不够圆”，而是：

> **业务功能已经专业，但主工作区布局、操作范围透明度、连续核查与追溯入口仍未达到同一成熟度。**

推荐方向不变：

1. **先保护查账主链路**：账表可读性、统一搜索、连续核查、选择与归集反馈。
2. **承认并保留已有设计**：不重复造 chips、页签、行高或折叠组件。
3. **再统一产品语言**：减少重复边框和相互竞争的按钮，收敛字体、数字、控件状态及弹窗规范。
4. **保持安静与密度**：延续 Claude Code 式简约和暖灰/陶土色，不靠大留白、大圆角或展示型 Dashboard 制造“设计感”。

## 三、最新版已经具备、应当保留的设计

1. **本地查账闭环完整**：从导入、科目、明细到凭证、关注和问题归集，主任务不依赖 AI 才能成立。
2. **数据保护较成熟**：文件指纹、预检、重复导入处理、按工作表提交、快照与变化复核均已实现。
3. **批量操作有专业基础**：同凭证分录去重、跨页勾选、Shift 连续选择、框选复制和合计适合真实查账。
4. **筛选结果已有可见上下文**：明细具备可换行条件 chips、逐项删除、清除全部、表头激活筛选与排序箭头。
5. **问题工作台已有基本主从结构**：目录支持即时搜索、双击和 Enter 打开；详情已有“相关凭证/问题记录”页签，默认相关凭证。
6. **凭证已有紧凑策略**：按分录数调整高度，固定显示借贷合计与差额，备注默认折叠，关闭前有保存保护。
7. **AI 已有渐进收纳与发送边界**：历史批次、结果通道和高级筛选默认收在“更多选项”；发送前展示实际字段并等待确认。
8. **已有紧凑密度意图，但行高联动尚未收口**：主题初始声明普通 32px、紧凑 27px；运行时普通表又会按字号改为 `max(28, size+16)`，紧凑表仍固定 27px。应修正这套联动，而不是再增加新的密度档位。
9. **视觉基调已有辨识度**：暖色中性色与低饱和陶土主色值得保留，问题主要是执行一致性，而非方向错误。

## 四、总体诊断

### 4.1 视觉审美

当前已有“安静”的基础，但仍有以下体系不一致与可读性缺口：

- **控件语言不统一**：ttk 按钮与 Canvas 圆角按钮并行，主操作在不同窗口中的样式和位置不稳定。
- **层级较依赖边框**：表头、工具条、面板、输入框和底部区域都有边界，容易形成矩形拼接感。
- **颜色语义未彻底收口**：全局 token 之外仍有借贷行色、关注行色和提示色硬编码。
- **小字对比度有明确缺口**：当前 `MUTED #77766F` 在 `CANVAS #FAF9F5` 上为 **4.33:1**，在 `SIDEBAR #F0EEE6` 上为 **3.93:1**，在 `ACCENT_SOFT #F1E3DD` 上仅 **3.64:1**。它大量用于 11–12px 辅助文字，不能只凭“看起来柔和”接受。主按钮白字与陶土底为 **5.49:1**，这一组可以保留。
- **圆角问题是体系断裂，而非数值太小**：现有 Canvas 控件使用 8/12px 圆角，ttk 控件则基本为直角。应先统一使用场景和状态，再收敛数值，不需要全盘自绘圆角。

解决方式不是扩大圆角，而是减少无意义边界、建立稳定对齐、明确文字和数字层级，并统一状态反馈。

### 4.2 布局与密度

默认 1160×690 对单账表基本可用。打开右侧问题工作台后，当前算法会按列最小宽度与弹性余量比例收缩表格；空间继续不足时会自动拆出独立窗口。

代码能确认空间策略，但实际截断程度、滚动频率和窗口跳体感仍待实测。设计上应坚持：**辅助面板应适应查账主任务，而不是让主账表为辅助面板让渡可读性。**

### 4.3 交互与反馈

当前最影响效率的是用户需要记住界面未充分表达的规则：

- 勾选凭证优先于框选范围，但操作入口没有持续说明范围来源。
- 加入问题会自动关注，但确认前没有明确说明。
- 明细主界面没有可见的通用搜索入口。
- 凭证没有上一张/下一张，连续核查需要反复回列表。
- 普通凭证来源列不仅默认隐藏，在显示设置中也无法开启。
- 部分空状态无法区分“无数据”“搜索无结果”和“当前科目无分录”。

### 4.4 产品完成度

当前更像“功能已成型、设计系统尚未收口”的专业工具，而不是需要推倒重来的原型。主要差距是：

- 高频工作流还没有完全围绕连续核查节奏组织。
- 组件焦点、字号缩放和跨平台键盘行为覆盖不完整。
- 入口归属与页面上下文不够一致，例如所有页面始终显示主色“导入表格”。
- 历史截图、宣传素材和说明文档与当前版本存在差异，容易继续传播旧界面认知。

## 五、最值得重新设计的九个区域

### 区域 1：明细账与问题工作台的空间关系

**优先级：P0；难度：中高**

#### 当前已实现

- 右侧问题区与计算器可切换，支持拖动调宽、停靠和用户主动拆成独立窗口。
- 问题目录已有即时搜索、双击和 Enter 打开；详情已有相关凭证与问题记录页签。
- 工具区关闭后会恢复表格列宽与横向滚动位置。

#### 仍有差距

- 问题区默认 400px，计算器 300px（`workbench.py:167-218`）。
- 工具区打开时，主表按最小宽度和弹性余量比例收缩，没有针对摘要、往来单位和金额设置差异化保护（`table_layout.py:22-71`）。
- 空间不足会自动拆出独立窗口，而非仅响应用户显式动作（`workbench.py:584-620`）。
- 详情中切换其他问题仍主要依赖返回目录，当前问题上下文可以进一步持续化。

#### 目标方案

1. 为主表设置可读宽度下限，不再等比例挤压所有列；超出时保留横向滚动。
2. 问题区建议从 360px 起步，可在约 320–420px 间调整，最终阈值由实测校准。
3. 宽屏停靠；空间不足时由用户主动打开覆盖式抽屉，不再自动拆窗。
4. “独立窗口”保留为显式选择。
5. 详情顶部保留当前问题切换入口，减少返回目录的往返。
6. 保留现有相关凭证默认页和问题记录页签，不重复重构已成立的结构。

#### 交互与效率变化

打开问题区后仍能直接读摘要与金额；缩窄窗口不会突然改变窗口空间；切换问题不必反复回目录。实际减少多少滚动和悬停，需要后续运行态测量。

### 区域 2：明细搜索、筛选与排序

**优先级：P0；难度：中**

#### 当前已实现

- 日期、摘要、借方、贷方和原币金额具备列筛选。
- 日期支持跨年度月份选择，金额支持比较与区间条件。
- 条件 chips 支持换行、逐项删除和清除全部。
- 表头已显示激活筛选、条件摘要和排序箭头（`ui.py:3525-3566`）。
- 科目树支持编码/名称搜索、保留祖先路径和展开状态。

#### 仍有差距

- 当前明细工具条没有通用搜索输入框（`ui.py:2185-2257`）。
- 后端仍有广义搜索能力，但当前没有可见入口；遗留 `submit_detail_search()` 实际会转成“摘要包含”条件，而不是通用搜索（`ui.py:3097-3100`）。
- 科目范围与筛选条件的清除逻辑不同，用户需要理解两类范围的边界。

#### 目标方案

保留现有 chips、列筛选和表头状态，只补一条清晰的主查询入口：

```text
[科目范围：全部科目 ⌄] [搜索摘要、凭证号、科目、往来单位、辅助核算…] [筛选 2] [更多]
```

- Enter 执行，`Cmd/Ctrl+F` 聚焦，明确搜索覆盖字段。
- 已激活条件继续使用现有 chips，没有条件时不占高度。
- 分别提供“清除搜索/筛选”和“清除科目范围”，避免一个按钮承担不可见规则。
- 保留列筛选弹窗和现有排序状态，不重新造一套筛选系统。
- 查询期间保持表格结构稳定，避免控件跳动。

#### 交互与效率变化

用户可以从凭证号、往来单位、辅助核算或摘要等熟悉线索开始，不必先理解五类列筛选；已有筛选仍能精确控制。

### 区域 3：凭证选择、详情与连续核查

**优先级：P0；难度：中高**

#### 当前已实现

- 同一张凭证的多条分录自动去重，支持 Shift 连续勾选、本页全选和跨页保留。
- 单元格框选支持多选区、复制、合计和键盘扩展。
- 凭证窗口按 2–8 行分录调整高度，固定显示借贷合计与差额。
- 关注备注默认折叠，自动保存与关闭前保护已经存在（`ui.py:3669-3825`）。

#### 仍有差距

- 只要存在勾选，后续操作就使用勾选范围（`voucher_selection.py:34-39`）；按钮和选择条尚未充分说明范围来源。
- 明细主要靠双击打开，没有 Enter 打开；凭证没有上一张/下一张和当前位置。
- 默认新凭证替换旧窗口，连续对照需要用户主动修改偏好。
- 普通凭证来源列被 `visible_columns()` 和显示设置同时排除，用户无法正常开启（`ui.py:110-120, 179-196`）。
- Esc 在表格选区和窗口关闭之间的实际事件传播、方向键与原生行导航的交互仍待实测。

#### 目标方案

1. 选择条明确区分：
   - `已勾选 3 张凭证（含跨页 1 张）· 后续操作使用勾选范围`
   - `当前框选涉及 2 张凭证 · 尚未勾选`
2. 勾选与框选采用不同视觉语义；存在旧勾选时，执行按钮旁持续显示范围来源。
3. 支持 Enter 打开当前凭证；凭证窗口增加上一张/下一张和“第 n/N 张”，顺序继承当前筛选结果。
4. 头部显示日期、凭证字/号、来源与复核状态；来源提供直接查看或复制入口，而不是仅增加一个隐藏列。
5. 保留当前紧凑高度、固定合计、折叠备注和保存保护。
6. 差额异常使用语义色，正常状态不抢眼。

#### 交互与效率变化

用户可在同一核查窗口连续过凭证，只在需要备注或归集时展开辅助操作；每次批量操作前都知道实际作用范围。

### 区域 4：关注、问题归集与复核状态

**优先级：P0（状态透明）＋P1（效率）；难度：中**

#### 当前已实现

- 关注支持备注、自动保存、变化检测和导出。
- 问题归集保存凭证快照，原凭证变化或消失后仍有追溯基础。
- 问题目录已有搜索和 Enter 打开。
- 问题快照复核与关注记录复核已有文案区分。

#### 仍有差距

- 加入问题会自动写入关注记录（`issue_store.py:89-103`），归集选择器却只提示加入和跳过重复（`workbench.py:851-886`）。
- 无搜索、无 Enter 确认、无最近使用的是**归集选择器**，不是问题目录。
- 完成反馈没有同时说明目标问题和同步关注结果（`workbench.py:900-911`）。
- 新建并加入后不会自动进入新问题详情；从目录发起时留目录，从其他问题详情发起时保持原详情。
- `locate_issue_voucher()` 已有定义，但全仓未发现 UI 调用点，定位原凭证的入口未闭环（`ui.py:2985-3008`）。

#### 目标方案

1. 归集确认区直接写：`将加入所选问题，并同步加入关注；已有备注不会覆盖。`
2. 归集选择器增加搜索、最近使用和当前问题置顶；Enter 加入所选，保留双击。
3. 当前已有打开问题时，提供低门槛的`加入当前问题`。
4. 新建并加入后提供`查看问题`与`继续核查`，不强制跳转。
5. 完成反馈写明目标问题、新增/重复数量及同步关注情况。
6. 按场景区分`确认问题快照已复核`和`确认关注记录已复核`。
7. 在问题相关凭证和快照中补`定位到当前明细`入口，复用已有定位能力。

#### 拖拽归集的定位：增强，而不是唯一入口

当前源码只保留单元格框选拖动；旧的“把凭证拖入问题”已于 2026-11-12 移除。因此不能把拖拽失效写成现行缺陷，也不建议为了回应“操作要自然”就优先恢复旧拖拽。

正确顺序是：先把显式选择、加入当前问题和结果反馈做清楚，再按需增加拖拽快捷路径。若后续恢复，至少应满足：

1. 使用专门的凭证拖动手柄，不与单元格框选、列宽拖动或勾选点击争夺手势。
2. 拖动开始即显示`将归集 3 张凭证 · 会同步加入关注`；只有有效问题落点高亮，其他区域保持安静。
3. 落点显示目标问题、已有重复数量和跨页范围；Esc 可取消，无效投放不写入。
4. 首版只接受已展开工作台中的明确落点，不做跨窗口边缘悬停自动展开；后者留到真实鼠标验收后决定。
5. 完成后反馈与显式加入完全一致，不能出现两条业务路径、两套副作用规则。

拖拽能减少熟练用户的指向—点击次数，但在 Tk 中要处理跨窗口、选区冲突和取消传播，**难度中高，建议列为 P2 增强**。它不是修复选择范围不透明的替代品。

#### 交互与效率变化

归集动作可预测，键盘流程完整；用户不必事后发现关注列表变化，也能从问题记录回到原始账表上下文。

### 区域 5：左侧导航、顶栏与功能归属

**优先级：P1；难度：中**

#### 当前已实现

- 侧栏支持 56px 图标模式与文字模式。
- 文字模式已有“账簿/核查”分组。
- 设置和账套固定在底部，低高度时会隐藏部分品牌说明。

#### 仍有差距

- 默认图标模式不显示分组标题，领域功能依赖抽象图标和 450ms tooltip（`navigation.py:67-96`）。
- 页面、问题工具、计算器和主体名单的视觉层级仍接近。
- 顶栏“导入表格”在所有页面保持陶土主色。
- 侧栏展开状态未持久化，窄窗口下不会自动退回图标模式。
- 文件菜单始终显示 macOS 的 `⌘I / ⌘O`，事件也只绑定 `<Command-i/o>`；非 macOS 缺少对应 Ctrl 绑定（`ui.py:2508-2546`）。
- `refresh_workbench_badge()` 会直接重写按钮文字，可能覆盖 `_nav_state()` 设置的“独立显示”状态；图标模式又因 `compound='image'` 看不到这类文字反馈（`ui.py:2445-2482`）。

#### 目标方案

1. 宽屏/首次使用默认显示图标＋文字，用户主动收起后记住选择。
2. 保留现有账簿/核查分组，让默认模式也能感知分组与当前位置。
3. 计算器和主体名单作为工具入口，视觉上弱于主页面。
4. 选中项使用浅底＋文字/指示条，不只改变图标颜色。
5. tooltip 缩短至约 250–300ms，并支持键盘焦点。
6. 顶栏主操作随页面变化；导入在不相关页面退为普通按钮或账套菜单项。
7. 按平台显示并绑定 `Cmd/Ctrl+I`、`Cmd/Ctrl+O`，菜单提示与实际事件必须一致。
8. 问题数量使用独立 badge，与“已停靠 / 独立显示”状态分离；图标模式用选中形状、计数和 tooltip 共同表达，不依赖被隐藏的文字。

#### 交互与效率变化

用户可从文字理解功能，从当前页面理解下一步；熟练用户仍能收起侧栏，但不以学习成本换空间。

### 区域 6：导入、字段映射与预检

**优先级：P1；难度：中高**

#### 当前已实现

- 单表调整窗口默认本地预览，`AI 建议列（可选）`已经是明确动作（`ui.py:1121-1128`）。
- 批量导入支持工作表清单、映射、预检、重复处理、部分成功与失败保留。
- 文件指纹、原表变化失效和按工作表提交均已实现。

#### 仍有差距

- 单表窗口同屏放置工作表、类型、表头、预览、多项映射、AI、Agent 和底部提示，信息阶段不够明确。
- **批量导入**仍默认自动表头审查；无 Key 时逐表出现“尚未设置 AI”，本地模式位于“手动设置”二级菜单（`ui.py:1429-1516, 1593-1651`）。
- 欢迎语`AI 辅助需确认后启用`与已有 Key 时批量自动表头识别之间存在预期不一致。
- 批量页同时承载进度、列表、详情、手动设置、AI 设置和 Agent 操作。

#### 目标方案

1. 保留现有窗口与功能，重组为`选择工作表 → 确认字段与预检 → 完成导入`三个阶段。
2. 批量导入默认先走本地规则；`AI 辅助识别`成为明确可选动作，未配置 Key 时直接继续本地或引导设置。
3. 启用 AI 前说明发送范围；涉及真实账目时提供轻量确认。
4. 字段映射按必需、常用和可选分组，可选字段折叠但不删除。
5. 原表预览与映射保持同屏，错误定位到工作表和字段。
6. Agent 接手收入`需要协助`，不与确认导入争夺层级。
7. 让欢迎页隐私文案与实际批量导入行为一致。

#### 交互与效率变化

用户先理解导入范围，再解决具体字段问题；AI 是可调用工具，而不是批量导入的前置门槛。单表已有的可选 AI 设计保持不变。

### 区域 7：AI 尽调线索与辅助复核

**优先级：P0（历史结果可读）＋P1（信息架构）；难度：中**

#### 当前已实现

- 历史批次、六种结果通道、科目/期间筛选已默认收进“更多选项”（`jev_ui.py:223-266, 323-329`）。
- 专项科目支持动态滚动，当前默认 14 个科目。
- 凭证抽查发送前已有逐页预览、实际字段展示与明确确认。
- 结果支持分类、批次、状态、过期和忽略等处理。

#### 仍有差距

- 首屏仍同时承担范围、进度、动态分类和结果表；展开高级选项后信息密度进一步增加。
- 未选专项科目表示审查全部已设置科目，需要阅读说明才能理解。
- AI 不继承当前明细筛选，从明细进入时范围关系不够直观。
- 分类固定按每行 7 个排列，窄窗口与大字号下仍待实测。
- AI 详情没有完整复用普通凭证的框选复制和计算能力。
- **过期结果存在可追溯性缺口**：删除原分录后，`ReviewDetail` 会从 `store.voucher_lines()` 取得空列表并直接访问 `lines[0]`，导致历史结果无法打开；这与 `refresh_staleness()` 会保留并标记过期结果的产品逻辑冲突（`jev_ui.py:627-648`，`jev_review.py:300-317`）。
- 设置入口重复：主操作条有“科目与提示词设置”，更多选项内又有“AI审查设置”；详情中“查看/编辑关注备注”和“保存关注与备注”还可能同时显示为主色，本地核查动作与 AI 结论的层级不够稳定（`jev_ui.py:195-227, 651-680`）。

#### 目标方案

1. 首屏优先呈现待核数量、当前批次、开始抽查和结果表。
2. 保留现有“更多选项”收纳；主结果视图可进一步收敛为待核、已处理、全部，其他状态留在高级筛选。
3. 动态分类改为带数量的下拉或可换行 chips，避免固定七列网格。
4. 专项范围默认以摘要呈现，如`本次范围：6 个专项科目`；开始后明确确认。
5. 从明细进入 AI 时明确`使用当前筛选范围`或`按专项科目新建范围`；若暂不继承，也应直接说明。
6. 历史批次和规则设置各保留一个稳定入口，避免重复。
7. AI 详情复用统一凭证核查能力，将模型判断和核查建议放在辅助区。
8. **过期历史必须可打开**：原分录已删除时，使用批次中已保存的发送内容、结果与规则版本构成只读历史详情，明确标注“原凭证已变化或不存在”；禁用依赖当前凭证的复核/归集动作并解释原因，而不是让窗口创建失败。
9. 保留现有发送前预览与确认，不削弱隐私边界。

#### 交互与效率变化

用户主要处理“哪些线索待核、下一条是什么”，需要时才管理分类、历史和规则；AI 发现线索后可顺畅回到本地复核。

### 区域 8：组件、表格、反馈、空状态与计算口径

**优先级：P1；难度：中**

#### 当前已实现

- 主题已有颜色、间距、圆角和字体 token。
- 主题已有普通/紧凑行高的密度意图，但运行时联动并不完整（`theme.py:166-173`，`ui.py:3899-3910`）。
- 空状态已有统一的图标＋标题＋说明＋动作组件。
- 关注与归集快捷键可配置，文本输入和模态窗口中有防误触处理。
- 计算器保存选区来源快照，支持加减、撤销和历史。

#### 仍有差距

- ttk 与 Canvas 按钮并行，不同窗口主操作样式不一致。
- Canvas 圆角按钮支持键盘触发，但没有清楚绘制的焦点态。
- 金额右对齐但未统一使用等宽数字。`set_font_size()` 只更新系统字体、`intro_font` 和 `welcome_font`，没有同步更新 `font_title / font_small / font_brand / font_mono`；`Compact.Treeview` 仍固定 27px，大字号下存在确定的截断风险（`theme.py:190-205`，`ui.py:3899-3910`）。
- 布局对硬编码像素依赖较强：AI 分类固定每行 7 个、凭证紧凑高度上限 440px、若干控件固定宽度；9–20 号字体切换后存在不同的重排风险。除上述行高问题外，具体窗口截断仍需运行态逐项验收。
- 关注搜索无结果与真正无关注共用空状态；科目范围不计入明细筛选空状态计数。
- 科目总览搜索无结果可能仍导向导入，AI 零结果缺少恢复型空状态。
- 计算器可对借方、贷方、原币和多币种选区直接求和，缺少口径分组或警示（`table_tools.py:415-440`）。
- Esc 在表格选区和窗口关闭之间的事件传播、方向键行为及原生菜单实际可用性仍应实测；不在本报告中把这些未运行场景写成已复现缺陷。
- 设置窗口的`保存并完成`与窗口 X 都调用 `_finish()`，同时字体等选项即时保存、快捷键等选项延迟保存，缺少一致的取消/未保存语义（`ui.py:216-404, 562-583`）。
- 尽调主体名单的新增、保存、删除都会调用 `refresh_details()` 重建明细表；而 `refresh_details()` 会重置选区、清空并重新查询。辅助名单维护不应让正在核查的明细丢失选择、滚动和焦点上下文（`ui.py:707-760, 3459-3523`）。

#### 目标方案

1. 统一按钮层级：每页最多一个主按钮，次按钮、静默按钮和危险按钮各有固定样式。
2. 统一输入框高度、边框、焦点与错误状态；弹窗主按钮固定右下。
3. 先修复字号、派生字体与两种行高的联动，再校准跨页面一致性和数字可读性；基准密度保持紧凑，不通过减少可见行数换取“高级感”。
4. 金额使用等宽数字，借方/贷方列至少容纳常见大额、千分位和两位小数。
5. 表格选中、勾选、关注、异常和框选不混用同一状态背景。
6. 空状态区分无账套、无业务数据、搜索无结果、筛选无结果、科目无分录、过期/未匹配，并提供对应恢复动作。
7. 计算前显示选区构成；混合借贷、原币/本币或多币种时分组或警示，不改变现有计算与快照能力。
8. 反馈按打扰程度分层：行内/状态栏用于成功，非模态提示用于可恢复问题，模态框只用于确认和必须处理的错误。
9. 让 `set_font_size()` 同步更新全部派生字体和普通/紧凑行高；紧凑表按实际字体行高加内边距计算，不固定 27px。9/13/20 号及系统中文字体均应无截断。
10. 设置弹窗明确区分即时生效与保存后生效的选项；有未保存修改时，关闭按钮提供保存/不保存/取消，无修改时直接关闭。底部保留稳定的取消与主保存动作，不让窗口 X 暗中等同于保存。
11. 主体名单、关注标记等局部更新只刷新受影响行和标识，保留明细查询范围、勾选、框选、滚动位置和焦点；只有用户明确改变查询条件时才重建结果上下文。

#### 交互与效率变化

控件行为更一致，数字更易比较，空状态能指导恢复；计算结果不会被误解为自动借贷净额或同币种合计。

### 区域 9：底部选择条、计算反馈、分页与全局状态

**优先级：P1；难度：中**

#### 当前已实现

- 表格底部有选区合计或框选快捷键提示。
- 明细和关注页另有勾选范围条、`本页全选`与`清空勾选`。
- 明细有独立分页/总数行，主窗口还有全局状态栏与忙碌进度。

#### 仍有差距

这四类信息分别由 `table_tools.py:129-132`、`voucher_selection.py:101-116`、`ui.py:2220-2233` 和 `ui.py:2346-2350` 创建，各自带 padding、换行和显隐规则。在空闲状态它们已经可能同时出现；勾选或框选后还会继续长高。历史截图可见多行连续底部提示，但具体占用像素仍需当前版本实测。

问题不是文字太多本身，而是**同一个“当前发生了什么”的上下文被拆到四层**：用户要在表格上方找动作，在表格下方找选择范围，再到窗口底部找结果反馈；小窗口还因此损失账表行数。

#### 目标方案

1. 合并为一个自适应账表底栏。空闲时约 30–32px：左侧显示总数、当前范围和期间，右侧分页。
2. 勾选或框选时，同一区域切换为约 40px 的操作态：直接写明范围来源、凭证张数/选区合计、`清空`、`关注`和`加入问题`，不再另起一条常驻操作栏。
3. 全局状态复用同一底栏的临时反馈区；成功信息短时停留，进行中的任务保留细进度，必须处理的错误留在相关字段或对话框附近。不要让全局状态、选区提示和分页同时抢三行。
4. 长期快捷键说明收进`?`提示、右键菜单或首次引导；用户开始框选后再显示与当前动作相关的短提示。
5. 窄窗口优先保留范围与主动作，`本页全选`、复制等收进`更多`，不要通过无限换行把底栏变成工具面板。
6. 切换勾选、框选、分页和任务状态时保持表格上沿与列位置稳定，避免视觉跳动。

#### 交互与效率变化

用户只看一处就能回答“选中了什么、接下来能做什么、操作结果是什么”。在 690px 或 520px 高窗口中，有望释放约一至两行的垂直空间；实际收益需要在当前运行态测量。更重要的收益是减少视线往返与状态误判，而不是单纯压缩界面。

## 六、推荐的整体视觉方向

### 6.1 设计概念：安静的账簿工作台

关键词：**克制、清晰、紧凑、可信、可回溯**。

- 暖白工作区像纸张，表格是真正主体。
- 陶土色只标识当前最重要的动作或激活状态。
- 分隔线很细，面板主要靠对齐和背景差分层。
- 圆角存在但不显眼，不成为设计语言主角。
- AI 不使用大面积紫色、渐变或发光效果，与普通核查工具共享语言。

### 6.2 需要减少的元素

- 同一视图内重复的外框与 LabelFrame。
- 所有页面常驻的主色导入按钮。
- 无数据时的大面积白表和无意义编辑器空白。
- 过多并列筛选项、长说明和常驻操作提示。
- 为圆角而新增 Canvas 容器或自绘复杂控件。

### 6.3 需要加强的元素

- 当前科目、当前筛选、当前凭证和当前问题的上下文。
- 数字列、凭证号和日期的扫描效率。
- 选择范围、保存状态和复核状态的可见性。
- 键盘焦点、按钮主次和弹窗操作的一致性。

## 七、DudLedger 设计规范 1.0 建议

### 7.1 色彩与语义色

| 角色 | 建议值 | 用途 |
|---|---|---|
| Canvas | `#FAF9F5` | 主窗口背景 |
| Sidebar | `#F0EEE6` | 导航与低层级区域 |
| Surface | `#FFFFFF` | 表格、输入与必要阅读表面 |
| Sunken | `#F5F3EC` | 表头、轻量工具区 |
| Ink | `#30302C` | 主文字 |
| Ink Soft | `#53524C` | 次文字 |
| Muted | `#6B6962` | 普通辅助说明；替代当前偏浅的 `#77766F` |
| Border | `#E3E0D7` | 默认细分隔线 |
| Border Strong | `#D4D0C6` | 输入框和必要控件边界 |
| Accent | `#A65036` | 唯一主操作、激活标记 |
| Accent Soft | `#F1E3DD` | 选中或轻量强调背景 |
| Success | `#356348` | 已完成、平衡等正向状态 |
| Warning | `#8A6D1A` | 待复核、口径提醒 |
| Danger | `#9E3B2E` | 删除、失败、真正异常 |

规则：

- 陶土色不大面积铺底，不同时突出多个按钮。
- 状态不能只靠颜色表达，需配文字或图标。
- 正文和辅助小字对比度目标至少 4.5:1，大字和关键控件边界至少 3:1；最终实现需实测。
- 建议的 `Muted #6B6962` 在 Canvas 上约 5.22:1、Sidebar 上约 4.73:1，可作为普通小字起点；在 Accent Soft 上仍只有约 4.39:1，因此浅陶土底上的小字应改用 `INK_SOFT` 或 `ACCENT_INK`，不能机械沿用 Muted。
- 借贷方向优先用列位置和标题表达，不建议长期用整行颜色区分。

### 7.2 字体、字号与数字

| 层级 | 建议 |
|---|---|
| 页面标题 | 15–16px，Semibold |
| 区块标题 | 12–13px，Semibold |
| 正文/表格 | 12–13px，Regular |
| 辅助说明 | 11–12px，Regular，不用于关键操作 |
| 表格金额 | 与表格同号，Menlo/系统等宽数字，右对齐 |
| 凭证合计 | 13–14px，Semibold，等宽数字 |

- macOS 中文优先系统字体/PingFang SC，Windows 使用系统 UI 字体。
- 金额、数量和页码尽量使用等宽数字，保证上下行比较。
- 全局字号调整必须同步表格行高、按钮、标题、备注、计算器和弹窗。

### 7.3 圆角、边框与阴影

- 现有 Canvas 控件使用 8/12px 圆角，与基本为直角的 ttk 控件并存。目标普通控件 4px、菜单/小弹层 6px；大型面板不必强行圆角。优先统一使用场景和状态，再收敛数值。
- 表格、侧栏和主工作区以直角和细分隔线为主，避免卡片套卡片。
- 默认边框 1px、低对比；焦点边框与普通边框明确区分。
- 阴影只用于真正浮于内容之上的菜单、弹窗或抽屉；停靠面板不用阴影。
- 优先共享 ttk 样式和布局，Canvas 仅用于确有价值的少量控件。

### 7.4 间距与尺寸

| Token | 值 | 常见用途 |
|---|---:|---|
| Space 1 | 4px | 图标与文字、紧凑控件间隔 |
| Space 2 | 8px | 同组控件、表头内边距 |
| Space 3 | 12px | 工具条、表单组间距 |
| Space 4 | 16px | 页面左右边距、主要分组 |
| Space 6 | 24px | 弹窗大分区，不用于每行表格 |

- 主内容页左右 16px，上下 8–12px；不叠加无意义容器 padding。
- 基准字号下普通表可从约 30–32px、紧凑表约 27–28px 起步，但最终行高必须由实际字体行高与内边距计算；大字号不得截断。先修现有普通/紧凑联动，不新增第三套密度。
- 基准字号下常规输入框与按钮以 30–32px 高为主，紧凑工具按钮可为 28px；字体放大时随内容增长，不用固定高度强行裁切。
- 图标按钮命中区域建议至少 28×28px，即使图标本身只有 16–20px。

### 7.5 图标

- 统一 16/20px 线性图标、笔画与视觉重量。
- 抽象导航功能保留文字；纯图标模式提供快速 tooltip 与键盘焦点名称。
- 关注、待复核、已保存等状态使用固定形状，不以 emoji 代替产品图标。
- 选中图标配合浅底或左侧 2px 指示条，避免仅换颜色。

### 7.6 按钮、输入框、菜单与弹窗

**按钮**

- Primary：每个视图最多一个，仅用于当前阶段主动作。
- Secondary：常规执行动作，白底细边框。
- Ghost：导航、展开、工具切换和低层级操作。
- Danger：只用于删除/移除等需确认动作。

**输入框**

- 标签与输入关系稳定；错误显示在对应字段附近，不只写到底部。
- 搜索框有明确范围占位符和清除动作。
- Disabled 仍需可读，必要时解释原因。

**菜单**

- 高频动作不放“更多”；更多只承载显示列、导出、恢复默认等次级操作。
- 原生菜单可保留系统外观，不必为视觉统一自绘；统一分组、命名、快捷键和危险项位置。

**弹窗**

- 标题说明任务，正文只保留当前任务，底部右侧主按钮、其左取消。
- 凭证查看是非模态连续工具；导入和设置按任务需要模态化。
- 不用自动拆窗解决响应式；窗口尺寸随屏幕和内容收敛。

### 7.7 表格与状态

- 保留当前表头筛选和排序状态，激活标记清晰但克制。
- 行 Hover 只提供轻微底色，不与选中/关注混淆。
- 选中行、勾选凭证、框选单元格是不同状态，文案和视觉不得混用。
- 金额空值与 0 保持现有区别，并通过对齐和占位增强可读性。
- 长文本优先给摘要足够弹性；tooltip 是补充，不应成为正常阅读的必经步骤。

### 7.8 控件状态矩阵

| 状态 | 设计原则 |
|---|---|
| Default | 层级稳定，不靠高饱和吸引注意 |
| Hover | 轻背景或边框变化，无布局位移 |
| Pressed | 轻微加深，立即反馈 |
| Selected | 浅底＋文字/指示条，持久可见 |
| Focus | 清晰可见的 1–2px 焦点环，与 Hover 不同 |
| Disabled | 不可操作且仍可读，必要时解释原因 |
| Loading | 保留原布局，防止按钮与表格跳动 |
| Danger | 仅用于破坏性动作或真实错误 |

### 7.9 动效

- 桌面 Tk 界面以即时、稳定为先，不为按钮和表格逐行加动效。
- 抽屉、展开收起可使用约 120–160ms、ease-out 的短过渡；若实现成本高或影响响应，宁可不做。
- 进度条只表达真实进度；无法确定时明确写“正在处理”。
- 数字、金额和选中状态不做滚动或闪烁动画。

## 十、推荐实施顺序

### 阶段 1：核心工作区与状态透明

- 主表宽度保护、工作台停靠/覆盖/独立窗口策略。
- 明细通用搜索入口与查询上下文。
- 选择范围来源文案与自动关注提示。
- 自适应底栏：先合并选择范围、计算反馈、分页和状态，不通过缩小字体换空间。
- AI 过期结果只读回退，先恢复历史记录可读性，再做结果页信息架构调整。

重点文件：`ui.py`、`workbench.py`、`table_layout.py`、`voucher_selection.py`、`table_tools.py`、`jev_ui.py`。

### 阶段 2：连续核查与归集效率

- 凭证 Enter、前后导航、来源入口与定位原凭证。
- 归集选择器搜索、最近使用、键盘确认与完成反馈。

重点文件：`ui.py`、`workbench.py` 中的 `VoucherActions` 与选择器实现。保持 `issue_store.py` 业务数据规则不变，除非另行决定调整自动关注逻辑。

### 阶段 3：导航、批量导入与 AI 信息架构

- 导航默认模式、状态持久化、独立计数与上下文顶栏。
- 菜单 accelerator 与 Cmd/Ctrl 绑定按平台统一。
- 批量导入阶段重组、本地优先与 AI 明确可选。
- AI 范围、分类、唯一设置入口和统一凭证复核。

重点文件：`ui.py`、`navigation.py`、`jev_ui.py`。

### 阶段 4：设计系统收口

- 颜色、字体、间距、按钮和弹窗规范。
- 修复 `set_font_size()`、派生字体和普通/紧凑行高联动；统一表格数字、焦点与空状态。
- 设置弹窗保存/取消语义，以及主体名单等辅助操作的局部刷新和上下文保护。
- 计算口径与快捷键发现；最后评估拖拽和必要动效，不用动画掩盖布局问题。

重点文件：`theme.py`、`widgets.py`、`table_tools.py`、`empty_state.py` 及各页面调用点。

## 十二、最终建议

后续实施不应从“全局替换圆角和颜色”开始，也不应重复开发最新版已经具备的 chips、页签、紧凑凭证和高级选项收纳。

最值得先完成的仍是三个能被真实使用感知的改变：

1. **打开问题工作台时，账表仍然好读。**
2. **从任意线索开始搜索，并始终知道选中了哪些凭证。**
3. **连续打开、核查、追溯和归集凭证，不必反复回列表。**

这三项完成后，再通过克制的色彩、字体、边框与状态规范统一外观。这样得到的是一次工作方式升级，而不是一次表面美化，也更符合 DudLedger 作为专业财务审查工作台的定位。
