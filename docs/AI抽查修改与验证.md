# AI 抽查修改与验证

当前实现已改为按提示词直接判断，见 [AI 审查按提示词判断与验证](AI审查按提示词判断与验证.md)。下文涉及 Noul 概率、三档阈值和模型联调的数据，是改版前的历史验证记录，不能用作当前直接判断模式的实测结果。

日期：2026-11-11。依据用户提供的《DuDLeger修改.md》及本次补充要求实施。测试范围仅限 AI 抽查及其设置、结果、历史兼容；没有运行其他功能测试。

## 已完成

- 默认优先使用阿里百炼 `decision-model-preview`，设置中可以改为 Jev 优先。默认回退顺序是百炼 → Jev → DeepSeek Flash；前一级未配置或余额／额度不足时尝试下一级。百炼接口404会提示检查业务空间地址并回退，不会误报为“未命中”。认证失败停止批次，普通限流按有限次数重试。
- 六类科目可多选：其他应收款、其他应付款、实收资本、资本公积、营业外支出、财务费用。未选择时默认这六类。先定位涉及所选科目的凭证，再发送同一凭证的完整分录，银行存款等对应分录仅作上下文。
- 使用 OR01—OR05、OP01—OP05、PIC01—PIC05、CR01—CR05、NOE01—NOE05、FE01—FE05 共30项独立问题。凭证只启用选中且实际涉及科目的问题，不调用综合 `review` 判断。
- 百炼和 Jev 使用原生 Noul；DeepSeek Flash 默认关闭思考，只返回命中编号、实际原文依据及信息不足标记。DeepSeek 不生成或伪装为决策概率。
- 百炼和 Jev 分别保存独立阈值，初始均为50／65／85；数值只是起始筛选参数，不代表两个模型已经完成同一校准。离线指标按实际模型分别统计，DeepSeek 使用明确命中，不套用概率阈值。
- 对多科目凭证按最多10项专项问题加1项信息不足提问分组，所有问题组保留同一凭证上下文。百炼适配器另有单次16题上限保护；不会因为30题的完整提示词超出请求字节预算而漏审。
- 结果显示科目、专项问题编号、实际模型和固定核查建议，可从详情加入现有或新建的尽调问题。核查建议由本地模板生成，不额外调用生成式模型。
- 保留预览确认、取消、缓存、过期校验和历史批次。原通用主题规则与专项规则独立，历史结果继续保留当时的提示词版本。优先模型可用时不使用其他模型的旧缓存代替。

## 设置与提示词

在“偏好设置”中选择抽查优先模型。三个模型的密钥在独立页签中保存，百炼另有官方接口地址和“测试百炼连接（虚构内容）”。密钥只进入系统安全凭据库；安全凭据服务不可用时只保存在当前进程内存，不写入项目或普通偏好文件。

本次已保存用户提供的百炼密钥到系统安全凭据库，并实际验证、保存其北京业务空间专属接口地址。未把密钥或账号专属地址硬编码到仓库。新安装默认提供阿里官方北京试用域名用于快速验证；长期使用可换成自己的业务空间专属域名。旧 DashScope 通用决策地址本次返回404，不能据此判断密钥无效。

在“AI 抽查提示词与专项审查设置”中可以编辑基础提示词、信息不足提问、30项问题及每项固定核查建议。百炼 OR03 另提供可编辑的“命中条件／排除条件”。保存生成新版本，仅新批次使用修改后的问题；历史批次不被覆盖。

**百炼需要的是协议及边界适配，不需要整体重写法律问题。** 它与 Jev 都支持 `state`、`questions`、`Noul(instructions, criteria)`，不应加入“生成JSON”“输出解释”等对话模型指令。实测中，百炼曾将股东借款附加分类为对外拆借；补充原生正反判定条件后，本轮正反例符合预期。DeepSeek 的 JSON 生成约束由独立适配器负责。

## 历史资料边界

本地程序可提供同名往来单位90日内、同币种、同金额的其他分录候选，最多20条，注明候选数量、是否截限、日期间隔和匹配口径。这些候选不等于完整资金流转或未清偿证明。

未提供真实账龄和完整银行流水时，不推断长期未收回或出资后异常转出。OR05、PIC05 仍需律师结合历史资料判断。本次没有自动生成账龄、虚构关联关系或认定违法。

## 验证结果

仅运行以下 AI 相关测试：

```bash
PYTHONPATH=tests .venv/bin/python -m unittest test_specialist_review test_bailian_review test_specialist_ui test_jev_review test_jev_ui test_jev_calibration
```

- 自动化：79项通过，覆盖科目范围、完整分录、原文校验、模型顺序、额度和接口不可用回退、独立阈值、分组预算、密钥安全、提示词版本、设置界面与历史 AI 结果兼容。
- 实际模型调用：三个模型各12个虚构正反例，共36例，本轮均符合预期。每个模型覆盖六类科目的正例和正常业务反例；没有发送真实账簿。
- 百炼完整流程：临时账套内3张凭证、6条分录全部完成，实际模型均为 `decision-model-preview`，结果正确保存并进入关注候选。
- Jev 实际调用版本为1.13；1.14的配置和返回兼容仅通过模拟验证。

原始结构化记录见 [三模型虚构样例联调](ai-review/虚构样例模型联调.json)、[百炼虚构样例联调](ai-review/百炼虚构样例联调.json)、[百炼完整流程联调](ai-review/百炼抽查完整流程联调.json)。虚构样例只证明这些案例的接入和筛选行为，不代表30项问题均已完成真实账簿准确率、漏报率或阈值校准。
