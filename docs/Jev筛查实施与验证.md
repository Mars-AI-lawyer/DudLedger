## 已接入的使用流程

“设置 → Jev 审查”维护应用级密钥；“AI 待核凭证 → 核查全部凭证”始终覆盖当前账套全部已导入明细，不再单独选择范围。逐页预览完整发送字段，明确确认后才开始后台请求。取消按钮为默认焦点。新批次以及重试、恢复均重新预览；确认后数据或规则变化会拒绝使用旧预览。

新版按凭证整体判断：只发送日期、科目、摘要、借贷金额，共用字段提取一次，完全相同的精简行去重。原始行、年度期间、凭证号、文件信息及用户名单留在本地用于归组与追溯。同号凭证仍按年度、期间、凭证字区分；无号记录按来源行单列。

整张凭证包含本年利润与损益类科目、借贷平衡、各行摘要均为明确结转描述时，标为“已跳过结转损益”，不请求 Jev。混合业务、非损益科目或描述不明确时不排除。进度分别显示成功、失败及跳过数量。

每张普通凭证固定一套 12 个问题，不再随分录数重复问题。按 UTF-8 字节保守控制每个片段的内容预算，超长摘要分段并保留边界重叠；不静默删除尾部。服务明确返回长度错误时继续拆分；规则本身过长或无法缩小则标为失败。分段主题信号取最大值，优先分取最高片段的完整评分分布；保存原始片段回答，单独标记需人工复核，不篡改模型的信息不足概率。

结果完成一张即可查看。默认“待核线索”保留达到优先分阈值、信息不足、判断不确定、分段核查或失败的凭证；谨慎档额外纳入优先级 2～4 概率合计 ≥0.35，或合同争议、劳动、诉讼、税务主题信号 ≥0.65 的凭证。一般尽调主题命中不直接提升优先分；金额只用于本地排序。该筛选策略尚未经过领域校准。

“更多选项 → 优先核查”仍按谨慎 40、中 65、宽松 85 筛选优先分，保留既有用户阈值。低分结果可通过“已完成结果／全部”抽查；未分析、失败、中断、取消和过期不等于无异常。详情明确评分属于凭证，逐行仅提供来源追溯；人工备注独立保存。未编辑过的内置旧提示词升级为新规则版本，用户编辑与历史批次保留。

每个账套同一时间一个批次；列识别、连接测试和法律筛查共用全应用四个请求上限。后台线程不操作 Tk，各线程使用独立数据库连接，界面通过队列读取进度。网络请求超时 25 秒，暂时性异常至多三次尝试；取消停止后续发送，已发出的请求可能仍完成并产生服务用量。错误提示使用固定文本，不把服务错误原文或认证头写入账套。

## 接口核对

实现依据官方 [Python SDK](https://docs.typesafe.ai/sdk/python)、[Noul](https://docs.typesafe.ai/primitives/noul)、[Score](https://docs.typesafe.ai/primitives/score)、[独立问题调用](https://docs.typesafe.ai/cookbooks/parallel_questions) 与 [模型说明](https://docs.typesafe.ai/models)。也检查了本机 SDK 类型与实际序列化行为。

使用 `TypeSafeClient.system_one`，固定 `jev-1.13.0`，每次 11 个 Noul 与 1 个五级 Score。优先分为 `score / 4 × 100`，表示核查优先级。Noul 表示特定命题的肯定概率，不作为风险严重程度；分段取最大值后只称线索信号，不称凭证整体概率。

官方模型页当前列明：总请求 64k tokens，state 加最长问题 32k tokens。程序另设更保守的 6,000 字节 state 预算及 48,000 字节请求预算，并限制内容加最长问题不超过 24,000 字节；字节数是长度保护，并非精确 token 计数。正常凭证一次请求，网络重试和超长拆分是例外；请求用量按凭证共用，不能逐行重复累计。

## 验证范围

本次验证使用临时账套、虚构材料及模拟服务返回，覆盖自动建账、目录偏好、同名保护、真实点击展开、结转排除、精简去重、长摘要尾部保留、服务超长降级、筛选策略和旧规则升级。74 项本地测试通过，差异格式检查通过。

新增验证：一张凭证完成、另一张仍等待时，进度显示 50%，列表立即出现已完成的低分结果；列表更新保留选中项。统一导入流程支持多文件，默认勾选批量 Jev 列建议，一次确认发送范围后逐张显示进度；用户手动保存的映射保留，有警告或失败时暂停导入。未启用 Jev 会提示本地识别可能有误。未打开账套导入时，保存窗口会显示建议位置并允许调整。Mac 顶部“文件”菜单可打开导入记录，“往来线索”不再展示。

- 超过 5,000 行的完整分析范围、分页边界、发送白名单、负数与零、双边金额和多币种。
- 提交前数据、规则或重新导入导致旧确认失效；等待请求名额后再次检查来源快照。
- 凭证整体评分及分段最高分，三档包含关系、精确阈值边界、高分待分类、低分不确定入口、部分凭证覆盖。
- 本地缓存、同凭证选定范围变化后缓存失效、规则版本更新、重新导入后过期、人工意见保留。
- 无效响应、认证失败、有限网络重试、取消保留已完成结果、启动后恢复中断状态、跨账套隔离与并发上限。
- v1 至 v5 的账套升级，原导入、浏览、关联方、关注凭证与 MD 导出回归。
- 实际 SDK 配合本地模拟 HTTP 返回，验证请求与响应结构；不依赖真实 API Key，不发送外部请求。
- Tk 界面的预览取消、确认开始、规则编辑、详情、人工复核及凭证穿透交互测试。

这些验证证明程序行为，不证明 Jev 对中文法律账簿的识别质量。尚未进行真实服务端端到端调用；Windows 系统凭据库、Windows 窗口外观与安装包尚未现场验证。截图工具当次超时，不能把交互测试描述为已完成截图目检。

## 中文效果校准：下一步需要律师标注

[72 条虚构样例](../examples/Jev中文校准样例.csv) 分为 48 条校准样例与 24 条独立验证样例，覆盖十类主题、常规经营、含糊记录、否定、冲回、复合主题和账簿内指令文本。全部人物、事项与交易均为虚构。

“开发建议主题”和“开发建议优先级”只是编写样例时的初始假设；**律师确认栏留空，不能把开发建议当作真实标签**。尤其是冲回、计提、普通保证金和无争议交易，应由律师结合本功能的核查目标确认边界。

1. 律师填写“律师确认主题”“律师确认优先级（0～4）”“律师确认信息不足”，并将“标注状态”改为“已确认”。验证集不要用于反复调整规则。
2. 将该 CSV 导入一个单独测试账套，确认摘要、日期、科目、借贷、币别和凭证号映射；其他标注字段保持不导入。每条样例的凭证号即样例编号。
3. 在软件内对该测试账套预览并确认 Jev 发送范围。测试样例也是显式云端请求，可能产生服务用量；开发过程没有自动执行这一步。
4. 对已完成批次运行以下本地统计命令（将账套路径和批次号替换为实际值）：

```bash
.venv/bin/python -m ledger_viewer.jev_calibration \
  --samples examples/Jev中文校准样例.csv \
  --book /path/to/test.sqlite \
  --batch 1 \
  --output /path/to/calibration.json
```

统计仅评估“任一主题概率达到档位阈值”的命中口径（与新版“命中问题”泳道一致），不代表新版“待核线索”组合策略的效果；组合策略须另外验证。统计口径：人工优先级 ≥2 为需核查正例，分别计算三档阈值的召回率、误报率及未命中样例；同时列示人工标注数、成功数、未分析或失败数、判断不确定数。未标注或分析失败不会当作阴性或正确结果；没有样本的指标为空。理想做法是按主题分别标注样例后逐主题统计。

5. 仅用校准集调整规则与阈值，保存形成新版本。确定后以独立验证集检查效果，记录实际模型、规则版本、阈值、样本与人工标注，再冻结本次采用版本。当前默认值尚未经过这一步，不承诺准确率。
