# UI 反馈修订与关联方审查验证

日期：2026 年 11 月 17 日

本次在现有 UI 调整基础上完成反馈修订，保留工作区已有改动。未自动打包、未提交或推送 GitHub，未打开可见测试窗口。

## 五项反馈的处理

1. **判断模型可选。** “设置 → AI 服务 → 凭证抽查优先模型”支持“百炼优先（默认）”和“Jev 优先”。偏好保存后用于新建批次，并在发送前预览中显示实际优先顺序。百炼仍需使用者确认免费可用才启用；未配置、额度不足或服务不可用时依次尝试其他模型，DeepSeek Flash 兜底。
2. **关联方清单进入模型上下文。** 百炼、Jev 和 DeepSeek 使用相同的结构化清单：每个主体的名称、别名、身份及与目标公司关系保持对应，备注不发送。补充三种模型共用的提示词，明确使用用户提供的身份和关系、不凭名称相似认定同一主体、不因客户或供应商列入名单就认定其为关联方。已有自定义提示词保留，一次性补充名单使用说明，历史规则版本保留。
3. **简化导入。** 默认自动使用 AI 分析表头和列映射，再在本机进行整表预检；无需逐字段手动对应。预检通过后仍需点击“确认导入”。“手动设置…”保留本地识别和手动列映射入口；明确保存的手动映射不会被重新启用 AI 覆盖。没有密钥或识别失败时给出设置、重试和手动处理入口，不提前写入账套。
4. **凭证操作简化。** 移除“复制来源”按钮，保留来源行文字供追溯。
5. **恢复数字字体。** 表格及金额显示恢复系统界面字体，不再强制使用 Menlo 等等宽字体；保留全局字号设置及按字体高度调整行高的逻辑。

## 顺带修复的逻辑问题

- 原来设置页虽写着 Jev 可选，但设置保存、批次范围及实际任务都固定为百炼优先；现已接通完整调用链。
- 批量导入主体名单时保留“与目标公司关系”；支持“名称、身份、与目标公司关系”表头，按列名识别，可换列顺序，身份可留空。文本格式支持 `张三｜股东｜持股30%`。
- 更换优先模型后，不复用另一个模型的缓存答案。
- 名称、别名、身份或关系改变后，新批次不复用旧上下文缓存；发送前旧预览失效，已完成的相关结果显示为过期。
- 页面原先只按账目版本决定是否重新检查过期状态，可能遗漏单独修改关系的情况；现在同时检查名单上下文，并在名单维护后刷新审查页面。
- 新名单上下文带版本标识，旧批次仍按原名单结构进行一致性校验，避免仅因结构升级就使旧批次全部失效。
- README 同步更新，修正“固定百炼优先”和将 Jev 描述为导入模型的旧说明。
