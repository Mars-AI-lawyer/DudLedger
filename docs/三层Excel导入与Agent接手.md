# 表头识别导入与 Agent 接手

更新日期：2026-11-04。旧版三层导入已改为仅 DeepSeek Flash 识别表头；为保持链接有效，文档保留原文件名。

## 内置导入

1. 选择一个或多个文件，在统一窗口勾选工作表。
2. 本地规则或已确认模板定位表头，多层表头在本地合并。
3. 使用 AI 时，仅向 DeepSeek Flash 发送一行逻辑表头，最多 40 列、每格 60 字。不发送业务数据行、疑点行、文件名、实际工作表名或路径。无法定位时要求手动指定表头，不扩大读取范围。表头文字本身也应注意保密。
4. 模型填写表类型与列映射，程序检查行号、列号及必填字段。完整数据解析、整表预检与账套写入在本地完成，原表不修改。
5. 疑点行由本地规则处理，无法安全处理时保留给人工；保存密钥不会启用疑点行联网分析。

旧的 Jev／自动逐层识别偏好统一迁移为 DeepSeek Flash。Jev 密钥仅供凭证尽调筛查使用，该功能的预览确认与发送范围另行控制。内置导入不再调用 Jev，也不自动转用其他服务。DeepSeek Flash 保留低思考配置；失败后可重试、手动设置或自行交给外部 Agent。

密钥优先存入系统安全凭据库；不可用时只保留在本次运行内存。已保存 DeepSeek 密钥后，建议列不再逐次弹窗。取消 AI 可仅用本地规则和手工映射。已手动保存的列设置不会被批量建议覆盖。

## 自行交给 Agent

“复制给我的 Agent”复制任务说明，包含所选文件、工作表、建议保存目录、本机 Python 与技能的准确位置，不包含密钥。只有用户主动粘贴到自己的 Agent 才开始外部处理。

- 随软件提供的 [导入技能](../ledger_viewer/skills/dudledger-import/SKILL.md) 供能读取本机文件和执行命令的 Agent 使用。
- 本地入口为 `python -m ledger_viewer.agent_import`，提供 `inspect`、`schema`、`validate`、`create` 四个操作。
- Agent 提交列映射 JSON，列号从 1 开始；程序负责金额解析、整表校验与账套写入。单列金额必须与方向同时映射。
- 方案绑定文件 SHA-256；文件变化须重新分析。排除行须说明理由，限定数据区域须解释区域外内容。
- 新账套在临时目录完整构建，全部导入和完整性校验通过后以不覆盖方式生成最终 `.sqlite`。失败不交付半成品，不修改已有账套。
- 来源、原行号、原行内容、预检报告与完整方案保存在本地账套。`--open` 可直接打开生成的账套。
- `--accept-warnings` 仅允许在核对后保留提醒，不能绕过关键解析错误，也不代表认可财务事实。

本地入口自身不联网，但外部 Agent 的模型可能接收它读取的内容；其读取范围不受内置“一行表头”约束，应自行控制授权和使用环境。

## 边界与验证

仅凭表头不一定能分辨所有会计含义，尤其是未知列名、多币种口径和同一工作表内多个不同结构区域。此时需人工核对，不自动发送真实分录补充分析。超过第 40 列的必要字段可以手动映射。缺失公式缓存、原数值已丢失的编码前导零等，仍需取得重算副本或原系统导出。

回归测试使用合成 Excel／CSV 与模拟模型响应，检查表头发送范围、多层表头、旧偏好迁移、疑点行留在本机、导入失败与 Agent 入口。不以模拟测试推断真实模型识别准确率。
