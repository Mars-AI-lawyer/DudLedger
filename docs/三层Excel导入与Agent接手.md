# 三层 Excel 导入与 Agent 接手

实施日期：2026-09-27。基础提交：`8c3988d`，保留其“序时账/明细账金额单列＋借贷方向”、用友 UFPrn、成对合计行和数量单价降噪等修复。本轮独立添加识别升级与 Agent 建账入口，不重写底层解析器。

## 用户流程

导入一个或多个文件，在偏好设置选择“自动逐层识别”（新版默认；原先保存的单模型偏好首次升级进入自动模式，之后以新设置为准）。

| 层次 | 做什么 | 何时进入下一层 |
|---|---|---|
| 1. Jev | 判断表类型、表头行和字段列 | 调用失败、映射无效、明确疑点、整表预检出现关键错误或提醒 |
| 2. DeepSeek 低思考 | 用同一份有限预览重新分析结构，填写列 | 仍未通过本地校验或仍有疑点 |
| 3. 我的 Agent | 用户点击“复制给我的 Agent”，将任务粘贴到自己的工具；Agent 阅读随软件提供的 skill，检查原表并创建新账套 | 需要原始资料才能解决的问题必须列出，不能假装已完成 |

Jev 通过则不调用 DeepSeek。每个模型每张表至多尝试一次；未配置密钥的模型跳过。两层均不可用时仍可直接使用 Agent 入口或手工映射，不强制购买模型服务。保留“仅 Jev”“仅 DeepSeek”选择以及取消 AI 后的手工导入。

批量导入一次确认两家服务的使用条件与发送范围：每张表前 20 行、前 40 列、每格最多 60 字，不发送整份文件或路径。第二层不自动扩大范围。取消确认不联网；关闭批量窗口会阻止后续升级与后续工作表请求，但已发出的请求不能撤回。

三层共同使用原来的本地解析器和整表预检，不能以模型置信度或“不报错”作为准确率。原表自身合计差异可能触发提醒，模型不能调平；经核对后可通过手工导入或 Agent 明确保留提醒。已经手动保存的列设置仍优先，不被批量建议覆盖。

## 第三层的交付方式

复制内容是一段可直接使用的任务说明，包含所选文件、工作表、建议保存目录、本机 Python 和 skill 的准确位置；不包含 API Key。它不需要公开链接，也不依赖某个厂商的插件安装方式。

- 随软件提供的 [导入 skill](../ledger_viewer/skills/dudledger-import/SKILL.md) 可由能读取本机文件并执行命令的 Agent 使用。Codex、Claude Code 等工具应以本机权限和实际执行能力判断，不把所有产品版本都宣称为已兼容。
- 本地入口为 `python -m ledger_viewer.agent_import`，提供 `inspect`、`schema`、`validate`、`create` 四个操作。
- Agent 写的是列映射 JSON，列号从 1 开始；程序负责金额解析、整表校验与账套写入。单列金额必须与方向同时映射。
- 方案绑定文件 SHA-256；文件变化须重新分析。排除行必须说明理由，限制数据区域必须说明区域外是什么内容。所选工作表的覆盖由 Agent 按复制任务核对。
- 新账套先在临时目录完整构建，全部导入、完整性校验通过后以不覆盖方式生成最终 `.sqlite`。失败不交付半成品账套，也不修改已有账套。
- 来源、原行号、原行内容、预检报告及完整方案保存在账套。用 `--open` 可在 DudLedger 直接打开；没有桌面环境时交付账套路径。
- `--accept-warnings` 只允许在核对后保留提醒，关键解析错误无法绕过。该选项不代表用户认可财务事实。

本地入口不会联网；外部 Agent 的模型仍可能接收它所读取的内容，不能把工具离线等同于整个 Agent 会话离线。

## 难点与已核查的开源参考

本轮只参考设计和公开文档，没有复制这些项目的代码。之前的项目资料确实引用过 react-spreadsheet-import 和 OpenRefine；下列链接本轮重新核查。

| 难点 | 参考 | 在本工具中的处理 |
|---|---|---|
| 表头匹配成功，但整表数据仍不可导入 | [react-spreadsheet-import](https://github.com/UgnisSoftware/react-spreadsheet-import) 分离选表头、匹配字段和数据校验，并提供行级/整表校验钩子 | 先校验映射，再完整预检；模型建议不能直接绕过预检写入 |
| 多行标题、表头不在顶部、文件包含多表 | [OpenRefine 导入说明](https://openrefine.org/docs/manual/starting) 支持预览、表头行配置、跳过顶部行和选择范围；多文件导入保留来源标识 | Agent 分段读取原行、指定表头和区域；保留文件与行号，不按扁平表盲目拼接 |
| 日期看起来相同但实际格式不同 | [react-spreadsheet-import 日期说明](https://github.com/UgnisSoftware/react-spreadsheet-import#dates-and-time) 提醒 Excel 日期使用数值且解析可能出现意外 | 使用现有日期解析与预检；模型不自行重写原始日期 |
| 低思考与关闭思考混淆 | [DeepSeek 官方思考模式](https://api-docs.deepseek.com/guides/thinking_mode/) 区分开关和强度 | `deepseek-flash` 使用 `thinking.type=enabled`、`reasoning_effort=low`，不再关闭思考 |

后续优先补充真实脱敏样表：三级及以上合并表头、同表异构区域、标题中隐含期间/单位、公式缓存缺失和超过预览范围的关键列。样表验收应核对原行与金额、期间、凭证分组、排除原因，不能只统计“导入成功”。

## 已知边界

1. 内置模型仍限于 20 行 × 40 列预览；第三层的本地 `inspect` 可读取更深行及全部列。
2. 一张原工作表内多个不同结构区域分别映射、跨列拼接、任意金额单位缩放尚未实现。不能声称 skill 能解决所有 Excel 版式。
3. 缺失公式缓存、原数值已丢失的编码前导零等，模型无法可靠恢复；应取得重算副本或原系统文本导出。
4. 通用 skill 已随项目提供，但尚未逐一实测各厂商 Agent，也尚未提供公开链接、URL 协议或 MCP 服务。可复制的本机说明是本版入口。
5. 原子生成使用目标目录内的硬链接；支持本机常用文件系统。在不支持硬链接的文件系统上会报错，不降级为覆盖已有文件，应选择本机目录保存。
